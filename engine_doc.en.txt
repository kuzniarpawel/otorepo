This document describes the public and internal helper API of the engine and the adopted
conventions. Keep it updated as the engine evolves.

--------------------------------------------------------------------------
 CONVENTIONS AND COORDINATE SYSTEMS
--------------------------------------------------------------------------
Head frame:  x = right, y = up (skull), z = forward (nose).
World: "up" axis = +y; world gravity = (0,-1,0).
Sides (ear/side): "L" = left ear, "P" = right ear.
Canals (canal): "posterior", "horizontal", "anterior".

Quaternion: q = [w, x, y, z]; rotates HEAD vectors → WORLD
            (v_world = q ⊗ v_head ⊗ q*).

Nystagmus components (anatomical, patient frame), returned as {h, v, t}:
   h: + to the right / − to the left        (horizontal)
   v: + upward / − downward         (vertical)
   t: + upper poles to the right / − to the left  (torsional)

Ewald's laws used in the engine:
   I   — plane specificity: the fast-phase axis of a given canal (quickPhase)
   II  — horizontal canal: AMPULLOPETAL flow is excitatory; excitation > inhibition
   III — vertical canals: AMPULLOFUGAL flow is excitatory

--------------------------------------------------------------------------
 PUBLIC API (returned from the module)
--------------------------------------------------------------------------

— STAGE 0 (rule-based) ——————————————————————————————————————————————

isExcitatory(canal, flow) -> bool
   Whether the given flow direction excites the canal (Ewald's law II/III).
   flow: "ampullopetal" | "ampullofugal".
   Returns: horizontal → (flow==="ampullopetal"); vertical → (flow==="ampullofugal").

quickPhase(canal, ear) -> {h, v, t}
   Fast-phase axis for canal EXCITATION, ipsiversive to the ear (Ewald I).
   ear: "L"|"P". (ipsi = ear==="P" ? +1 : -1)
   horizontal → {h:ipsi, v:0,    t:0}      (horizontal toward the excited ear; torsion masked)
   posterior  → {h:0,    v:+0.93,t:ipsi}   (upbeat + torsion toward the ear; real v:t≈0.93:1)
   anterior   → {h:0,    v:-1,   t:0}      (PURE downbeat; geometric torsion ~0.78 MASKED — NYS_SHOW.anterior.t=false)
   NOTE — CLINICAL MASK (NYS_SHOW): quickPhase returns the UI convention for BPPV (anterior = pure downbeat,
   horizontal without torsion). The FULL geometry (anterior torsion PRESERVED, for lateralization) → NeuroVOR.qpFull()
   / Vestibular.nysMag(); used by the HINTS layer (vHIT saccade / verticalBeat / SCDS). See the "CLINICAL MASK" section.

nysMag(canal, ear) -> {h, v, t}
   Full geometric proportions of the nystagmus from REAL canal normals (CANAL_NORMALS), normalized
   to max=1. Does NOT apply the NYS_SHOW clinical mask (anterior-canal torsion PRESERVED) — cf. quickPhase
   (same geometry, masked to the BPPV convention). Source of the full geometry for NeuroVOR
   (qpFull → vHIT saccade / verticalBeat / pressureStimulus-SCDS). ear: "L"|"P".

nystagmus({canal, ear, excited=true}) -> {h, v, t}
   Fast phase for the given, excited/inhibited canal.
   Inhibition (excited=false) reverses the sign of all components.
   Future use: unilateral loss (excited:false), push-pull.

— STAGE 1 (static geometry) ————————————————————————————————————

gHead(q) -> [x, y, z]
   The gravity vector expressed in the head frame for orientation q.
   Upright-standing head (q=[1,0,0,0]) → [0,-1,0].

qSupineYaw(deg) -> q
   "Supine head-hanging" orientation (a -100° pitch about the interaural axis)
   with a head yaw of `deg` about the skull axis (y). Use: Dix-Hallpike (±45),
   Roll (±90). Note: positive deg = right ear down (3D convention, NOT the UI schematic).

qPitch(deg) -> q
   Pure pitch about the interaural axis (x). +deg = bow forward (bow),
   -deg = lean back (lean). Use: Bow & Lean test.

position({canal, side, variant, q}) -> {excited, mag, h, v, t}
   Static stimulation of the AFFECTED canal in head orientation q.
   side: "L"|"P"; variant: "canalo" (geotropic) | "cupulo" (apogeotropic).
   Mechanism: projection of gravity onto the canal's excitation axis → flow → Ewald.
     - horizontal:  proj = g · uHC(side);  excited = (variant==="cupulo" ? proj<0 : proj>0)
                 (Ewald II: geo/apo reverse)
     - vertical:  proj = g · GEXC[canal];  excited = proj>0
                 (Ewald III; no geo/apo reversal for vertical canals)
   excited: bool; mag = |proj| (raw force); {h,v,t} = quickPhase with the sign of excitation.
   VALIDATED: Dix-Hallpike (posterior), Roll (geo/apo), Bow & Lean.

— STAGE 2 (particle dynamics) ————————————————————————————————————————

simulateCanalith({canal, side, timeline, q0=null, dt=0.05, tauP=6.5, tauC=5, gc=1.6, phiExit=178, fStat=0.04, adh=0.2, size="medium", rep=0, fatTau=2.0, fatFloor=0.06, crusArc=12, crusGrav=0.6, crusFling=145}) -> [{t, xi, phi, exited}, ...]
   Simulation of CANALITHIASIS: the otolith as a particle on the canal arc.
   [PHENOMENOLOGICAL MODEL — a proxy for the dynamics, not full hydrodynamics; see the "MODEL NATURE" header
    and "SIMPLIFICATIONS RELATIVE TO FULL MODELS".]
   timeline: array of segments [{q, tTrans, tHold}, ...]
       q      — target orientation (quaternion)
       tTrans — transition time to q [s] (slerp interpolation from the previous q)
       tHold  — hold time at q [s]
   q0 — STARTING orientation (quaternion); default null = the q of the FIRST segment (backward compatibility).
       NOTE (semantics of the 1st segment): with q0=null the first segment does NOT interpolate from the neutral position —
       its tTrans is time ALREADY IN the starting position, NOT a transition from sitting. To force a transition from a given
       orientation to the 1st q, pass q0 (e.g. [1,0,0,0] = neutral head). UI convention: the 1st segment has tTrans:0,
       and the transition is realized by the NEXT segment (maneuverTimeline: tTrans:0.8 per step). Analogously for simulateCupulolith.
   Model:
       φ — arc angle of the particle (ampulla φ=0, exit/common crus φ≈180°); lower bound 3°.
       Overdamped motion (Stokes drag, no inertia):
           dφ/dt = (g_head · tangent(φ)) / tauP
       Cupula (first-order model, long time constant):
           dξ/dt = -ξ/tauC + gc · exc · dφ/dt   (exc: +1 vertical / -1 horizontal)
   OTOLITH ADHESION (latency):
       The otolith is initially attached; the bond (adh) is broken by a sustained tangential force
       above the threshold fStat → a delayed start = LATENCY. A stronger provocation = shorter
       latency (consistent with the clinic). Once broken, the otolith no longer re-attaches in this session.
   COMMON-CRUS CHAMBER + EXPULSION INTO THE UTRICLE (VERTICAL canals: posterior+anterior; the horizontal has no crus):
       Anatomically, "reaching the end of the arc" (φ=phiExit) ≠ "falling into the utricle" — these are TWO events.
       • HORIZONTAL CANAL: no common crus → the non-ampullary end opens DIRECTLY into the utricle: after φ≥phiExit
         the otolith enters the utricle ONE-WAY (exited). (Unchanged from the previous version.)
       • VERTICAL CANALS (crusArc/crusGrav/crusFling): after reaching the crus (φ≥phiExit−crusArc) the otolith ENTERS
         THE CRUS CHAMBER and PARKS — it leaves the sensitive canal, the cupula relaxes (ξ→0, no nystagmus), it waits for
         expulsion into the utricle. Two physiological expulsion routes from the crus:
           – GRAVITATIONAL (slow): with the head UPRIGHT (sitting) the utricle is below the crus → the debris falls in. Condition
             −gHead_y > crusGrav (projection of gravity onto the crus→utricle axis ≈ [0,−1,0]). Gives Epley expulsion AT
             SITTING (step 5) + a LIBERATORY nystagmus where it clinically occurs.
           – INERTIAL (fast): an abrupt flip through a large angle (Semont ~180°) throws the debris out of the crus by inertial
             forces regardless of gravity. Proxy: segment transition angle > crusFling (with a ~uniform transition
             time, a large angle ≈ a large angular velocity). Sustains Semont expulsion AT THE FLING (step 3).
         Expulsion advances φ: (phiExit−crusArc)→phiExit over ~EXPEL_DUR(1.2 s) → an ampullofugal nystagmus TRANSIENT
         (the SAME sign as the original) = liberatory/confirmatory. exited=true one-way (blocks the reversed phase).
       Backward motion in the canal lumen (dφ/dt<0, before the crus) → ξ<0 → REVERSED nystagmus.
       VALIDATION (offline, real generated plans, both sides): Epley expulsion/liberatory at STEP 5 (sitting, ξ~0.31);
       Semont at STEP 3 (fling); Yacovino at STEP 3 (chin to chest); horizontal canal (Lempert/Gufoni) UNCHANGED;
       Gufoni apo still does not clear (conversion). Diagnostics (a single lying position): the debris parks in the crus
       without expulsion → nystagmus crescendo→decrescendo (extinguishes), the debris does NOT "vanish" (more physiological).
   CONSTANTS CALIBRATED TO THE LITERATURE (posterior canal, canalithiasis):
       latency ~1–3 s, time to peak ~7–9 s, attack duration ~25 s;
       tauC=5 s corresponds to a long cupular/canal time constant (~4–6 s).
   Returns: t [s], xi (sign = excitation/inhibition), phi [°], exited (bool).
   Tuning parameters: tauP, tauC, gc, phiExit, fStat, adh.
   PARTICLE SIZE/DENSITY (size): "small" | "medium" (default) | "big" — or a number (radius multiplier r).
       Mapping SIZE_R = {small:0.78, medium:1.0, big:1.35}. Physical scaling from r:
         tauP ∝ r⁻²  (Stokes settling velocity v ∝ r² → faster flow for a larger particle),
         gc   ∝ r³   (displaced volume/mass of endolymph → cupular deflection),
         adh  ∝ r    (detachment force of a sphere from the wall, JKR/DMT scaling).
       medium == r=1 → result IDENTICAL to the previous calibration (safe default).
       Emergently: LARGE = shorter latency, stronger/faster nystagmus, faster exit;
       SMALL = long latency, weak and slow course, MAY NOT reach φ=178° in the shortened holds
       of a maneuver (e.g. Semont/Yacovino) — consistent with the rationale of ~30 s holds for slowly settling
       fragments (Hain [2]) and with "extremely long-latency BPPV" [11]. Addresses the simplification
       "no effect of particle size" from the SIMPLIFICATIONS section.
   FATIGABILITY (rep) — a DIFFERENTIATING criterion canalithiasis↔cupulolithiasis [12].
       rep = the provocation repetition number in the same session (0 = first = full response). Mechanism:
       a compact cluster of otoconia DISPERSES on repetition (serial Dix–Hallpike) into smaller, less
       coherent fragments → weaker aggregate cupular deflection. The factor fatigueFactor(rep,{fatTau,fatFloor})
       scales gc → the AMPLITUDE ξ (and the nystagmus) decreases linearly; GEOMETRY/LATENCY UNCHANGED (the dominant,
       undisputed clinical effect is the amplitude drop). Defaults fatTau=2.0, fatFloor=0.06; rep=0 → factor 1
       → IDENTICAL result (backward compatibility). Example (posterior canal): peak ξ 0.81→0.51→0.33→0.22→0.15 for
       rep 0..4. CUPULOLITHIASIS (simulateCupulolith) has NO rep — the debris adheres to the cupula, does not disperse
       → does NOT fatigue; the difference is an emergent differentiating feature.

fatigueFactor(rep=0, {fatTau=2.0, fatFloor=0.06}) -> factor ∈ [fatFloor, 1]
   Pure fatigability factor: fatFloor + (1−fatFloor)·exp(−rep/fatTau); rep 0/negative/NaN → 1; monotonic
   decay to fatFloor; fatTau≤0 → RangeError. Exported to UI/diagnostics (serial Dix–Hallpike).

nystagmusPhase(xi, thr=0.05) -> "primary" | "reversed" | "none"
   Classification of the phase relative to the provoking direction:
   "primary" (ξ>thr, primary/liberatory), "reversed" (ξ<-thr, reversed), "none".

simulateCupulolith({canal, side, timeline, dt=0.05, tauCup=0.8, gain=1.0, size="medium"}) -> [{t, xi, target}, ...]
   size scales gain ∝ r³ (a heavier otoconia cluster → stronger cupular deflection); no latency
   (tauCup unchanged). SIZE_R as in simulateCanalith. medium == r=1 → identical result.
   Simulation of CUPULOLITHIASIS: otoliths attached to the cupula → a heavy cupula deflected
   DIRECTLY by gravity (static projection), without a free particle in the canal lumen.
   Model:
       target = CUP_WEAK · gain · |proj| · (excited ? +1 : -1)
                where proj/excited from position({canal,side,variant:"cupulo",q}) (Ewald's rule;
                horizontal: apogeotropic = reversed relative to geotropic)
                CUP_WEAK=0.6 — CUPULOLITHIASIS WEAKER THAN CANALITHIASIS [1] (debris attached to the cupula
                deflects it more weakly than a bolus of free otoconia driving the endolymph column). The SAME
                coefficient scales the diagnostic nystagmus of the "cupulo" variant (nysFromGeom) — a single source of truth.
       dξ/dt = (target - ξ) / tauCup           (fast relaxation)
   Emergent features (contrast to canalithiasis):
       - NO LATENCY (ξ follows gravity immediately; tauCup small)
       - PERSISTENCE (ξ holds the target as long as the position is maintained; no extinction)
       - SMALLER AMPLITUDE (CUP_WEAK): nystagmus less intense than in canalithiasis [1]
       - smooth reversal on position change
   Returns: t [s], xi (sign = excitation/inhibition), target (static target).
   Tuning parameters: tauCup, gain — TO BE CALIBRATED.

dynNystagmus(canal, side, xi) -> {excited, intensity, h, v, t}
   Conversion of instantaneous ξ (from simulateCanalith) into nystagmus components.
   excited = (xi>0); direction = quickPhase with the sign of excitation.
   intensity = min(1, |xi| · (excited ? 1 : 0.45))
               — Ewald II rectification: the inhibitory response is weaker.
   [2026-07-02] NOW THE SOLE SOURCE of nystagmus direction/strength/reversal in the ENTIRE application — diagnostics
   (via nysFromGeom→position) AND maneuvers (via the view: nysFromDyn/stepXiPeak in otorepo.html, outside
   the Vestibular module). Manual direction annotations for maneuvers (headNys.ear/intensity) REMOVED;
   direction+strength+reversal (ξ<0→inhibition) follow exclusively from this function. Validated by an Ewald
   audit for all maneuvers/sides (view_doc.txt: "ENGINE AUDIT AGAINST EWALD'S LAWS").

--------------------------------------------------------------------------
 INTERNAL CONSTANTS AND HELPERS (non-exported)
--------------------------------------------------------------------------
qmul, qconj, qaxis(ax,deg), rotv(q,v), dot3, nrm3, nrm4 — vector/quaternion algebra.
slerpQ(a,b,t) — spherical quaternion interpolation (with hemisphere handling and the near case).
Q_SUPINE = qaxis([1,0,0],-100) — base of the supine head-hanging orientation.

GEXC — excitation axes of the VERTICAL canals (in the canal plane; g·GEXC>0 = ampullofugal; axis = -e1):
   RP: norm(1,0,-1)  LP: norm(-1,0,-1)  RA: norm(-1,0,-1)  LA: norm(1,0,-1)   (anterior = -e1, consistent with CANAL_GEOM / the RESOLVED fix below)
uHC(side) — the ampullopetal axis of the HORIZONTAL canal (interaural + antero-posterior):
   P: norm(0.87,0,0.5)   L: norm(-0.87,0,0.5)
CK — mapping {canal,side} → GEXC key for the vertical canals.

CANAL_GEOM — arc geometry for the dynamics (e1=ampulla direction φ=0, e2=second plane axis,
             exc=sign of excitation):
   posterior  P:{e1 norm(-1,0,1),  e2 (0,-1,0), exc +1}   L:{e1 norm(1,0,1),  e2 (0,-1,0), exc +1}
   horizontal P:{e1 norm(0.87,0,0.5), e2 norm(0.5,0,-0.87), exc -1}
              L:{e1 norm(-0.87,0,0.5), e2 norm(-0.5,0,-0.87), exc -1}
   anterior   P:{e1 norm(1,0,1),   e2 (0,-1,0), exc +1}   L:{e1 norm(-1,0,1), e2 (0,-1,0), exc +1}
   Note: the ampullae of the posterior and anterior canals are on opposite sides (e1 reversed) —
   a result of calibration to ampullofugal flow in the provoking position.

--------------------------------------------------------------------------
 BIBLIOGRAPHY AND MODEL CONSISTENCY WITH THE LITERATURE
--------------------------------------------------------------------------
The engine is a REDUCED, phenomenological implementation of established biomechanical
BPPV models — it contains no new scientific hypotheses. Mapping:

[1] Squires TM, Weidman MS, Hain TC, Stone HA (2004). "A mathematical model
    for top-shelf vertigo: the role of sedimenting otoconia in BPPV."
    J Biomech 37(8):1137-1146.
    → The canonical canalithiasis model: an otolith settling under gravity with Stokes
      drag, transcupular pressure, cupular deflection. CONSISTENT with our
      dynamics layer (simulateCanalith), in a simplified version.
    → The MAIN mechanism of latency per [1]: no significant pressure until the otolith
      travels from the wide ampulla to the NARROW duct (pressure amplification).
      WE DO NOT MODEL THIS — see the latency annotation below.

[2] Hain TC, Squires TM, Stone HA (2005). "Clinical implications of a
    mathematical model of BPPV." Ann N Y Acad Sci 1039:384-394.
    → Clinical implications of [1]; the rationale for holding a position ~30 s in the CRP.

[3] House MG, Honrubia V (2003). "Theoretical models for the mechanisms of BPPV."
    → Both mechanisms (canalithiasis and cupulolithiasis) are physically plausible.

[4] Obrist D, Hegemann S (2008). "Fluid-particle dynamics in canalithiasis."
    J R Soc Interface 5(27):1215-1229.
    → Fluid–particle dynamics; the open question of whether otoliths adhere to the wall.

[5] Dai M, Klein A, Cohen B, Raphan T (1999). "Model-based study of the human
    cupular time constant." J Vestib Res.
    → Long cupular/canal time constant (~4–6 s). CONSISTENT with tauC=5.

[6] Schuknecht HF (1969). Cupulolithiasis (heavy cupula → immediate,
    persistent nystagmus). CONSISTENT with simulateCupulolith (no latency, persistence).

[7] Hall SF, Ruby RRF, McClure JA (1979). Canalithiasis (free fragments in the canal).
    CONSISTENT with the particle model. (cf. Brandt & Steddin 1993 — canalithiasis better
    explains latency and fatigability).

[8] Steinhausen (1933); Van Egmond, Groen, Jongkees (1949) — the torsional-pendulum
    model of the cupula. CONSISTENT with the first-order cupula.

[9] Ewald (1892) — Ewald's laws I/II/III. CONSISTENT with quickPhase / isExcitatory.

[10] Della Santina et al. (2005) — canal-plane orientations. The basis for the
     canal normals (GEXC, CANAL_GEOM) in an idealized version (45°).

[11] "Extremely Long Latency BPPV" (Res Vestib Sci, 2017) — very long latencies
     attributed to otolith ADHESION and their size. The basis for the adhesion hypothesis
     (our latency) as a minority mechanism.

[12] Dix MR, Hallpike CS (1952) — the original description of positional BPPV nystagmus and its
     FATIGABILITY (extinction/attenuation on repeated provocation). The dispersion mechanism
     of the compact debris: Brandt & Steddin (1993, [7]). The basis for the fatigueFactor (rep) factor:
     canalithiasis fatigues, cupulolithiasis (debris on the cupula) — does not.

ANNOTATION — LATENCY (a deliberate modeling choice):
  Our latency arises from otolith ADHESION (a bond broken by a sustained tangential
  force). In the literature this is an ACCEPTED but MINORITY hypothesis, invoked
  especially for long latencies (Hain/dizziness-and-balance; "Extremely Long
  Latency BPPV" 2017). The MAINSTREAM [1,2] explains latency by the ampulla→narrow-duct
  geometry (pressure amplification), which we do NOT implement. Other hypotheses:
  inertia of the otolith clot. We reproduce the correct clinical behavior
  (latency present, shorter with a stronger provocation) by an alternative route.

SIMPLIFICATIONS RELATIVE TO FULL MODELS:
  - a "tangential gravity → flow" proxy instead of the full transcupular pressure ΔPc;
  - no amplification in the narrow duct (the main latency mechanism per [1]);
  - particle size: SUPPORTED as a scaling parameter (size → tauP∝r⁻², gc∝r³, adh∝r);
    still no wall interactions and no velocity storage;
  - cupulolithiasis WEAKER than canalithiasis [1]: MODELED by a single coefficient CUP_WEAK=0.6
    (amplitude multiplier of ξ in simulateCupulolith AND of the diagnostic nystagmus of the "cupulo" variant in nysFromGeom);
    residual simplification: the coefficient is GLOBAL (not per-canal or per-geometry), a calibration value;
  - fatigability (dispersion of the compact debris on repetition) MODELED as a factor scaling
    amplitude (fatigueFactor / the rep parameter in simulateCanalith) — NOT as an explicit simulation of many
    particles with different trajectories; cupulolithiasis is deliberately without fatigability (a differentiating feature) [12].


=== MANEUVERS AS QUATERNION TIMELINES (entry into the dynamics) ===
The maneuver plan → engine bridge. simulateCanalith uses ONLY gHead (gravity in the head frame),
so we define a step by the target gHead and build a quaternion qFromG(g).
Head frame: x=right ear, y=skull(+crown), z=nose.
Functions (after xiEnvelope in the file):
- qFromG(g) → a head→world quaternion such that gHead(q)=g.
- rotYg(g,deg) → rotation of gravity about the skull axis (neck yaw).
- BASE_G[body|face] → gHead for yaw=0 (sit/sideL/sideR/prone/sitFront). Yaw: rotYg(g,-yaw).
- LEAN_G[leanL/R|up/down] → FINAL gHead for the Semont flings (neck yaw built in; mirrored by side).

GOAL AND PHILOSOPHY ("first-principles")
 We do not code the APPEARANCE of a pathology, but the PHYSIOLOGY: the resting activity of the labyrinths,
 Ewald's law with an inhibitory cut-off, fixation suppression (flocculus), canal VOR gain,
 the neural integrator, and the graviceptive axis (otoliths/MLF). The signs — spontaneous
 nystagmus, its dependence on fixation and gaze, the head impulse (vHIT) result,
 skew deviation — FOLLOW from the asymmetry of a few parameters. A layer INDEPENDENT of
 the BPPV dynamics (simulateCanalith); it shares only the direction conventions (quickPhase)
 and the frontal camera (mirror cam.right[0] = -1, like nysFromGeom/nysFromDyn).
 It realizes the todo item: "Other states (excited:false / push-pull): unilateral
 vestibulopathy, central nystagmus".

CONVENTIONS
 Sides: "P"=right=+x (right ear), "L"=left=-x. Afferent frequencies in Hz.
 Slow-phase velocities (SPV) and drift in °/s. Gaze angle gazeDeg: + = to the right (P).
 The "head-frame" sign h/t as in Vestibular; `dir`/`tdir` = the SCREEN sign after camera mirroring.

 afferent(tone, drive) -> Hz                                                                  [H1][H2]
   The afferent after RECTIFICATION: max(0, min(R_SAT, tone+drive)). Inhibitory cut-off (≥0) +
   saturation (≤R_SAT=300). A shared primitive: rest (drive=0) and head impulse (drive≠0).

 spontaneous(p) -> {kind,h,v,t,dir,tdir,vdir,strength,spv,beatEar,lesionEar}                  [H1][H2]
   STAGE 1 — SPONTANEOUS nystagmus from tonic asymmetry (push-pull). The brain estimates head velocity
   from the difference of the horizontal-pair afferents: Ω_est ∝ (rateL − rateR). A tonic asymmetry mimics a steady
   rotation → the SLOW phase toward the weaker labyrinth, the FAST phase (the visible beat) toward the stronger one.
   spv = SPV_MAX·|toneL−toneR|/R0 (SPV_MAX=12°/s, R0=90). Horizontal-torsional nystagmus (tH = 0.5·h).
   Direction FIXED regardless of gaze — a PERIPHERAL feature.
   STAGE 7 (E3): a VERTICAL-TORSIONAL component from the vertical-canal pairs (verticalBeat) is added to the horizontal —
   fields v/vdir, tV, t=tH+tV, spvV/strengthV; kind="verticalTorsional" when the vertical dominates. Vertical canals
   healthy → v=0, spvV=0 (the horizontal case unchanged). See verticalBeat (STAGE 7).

 suppressionFactor(p, fixOn) -> [0..~1.5]                                                       [H3]

   STAGE 2 — FIXATION SUPPRESSION. eye = VOR − fixationGain·retinal_slip. fixOn=true (light):
   peripheral (fixationGain≈0.9) fades (×0.1); central (≈0) persists; <0 = paradoxical enhancement.
   fixOn=false (Frenzel/darkness): the full slow phase. `suppressed` = clinically "suppresses with fixation".

 headImpulse(p, toSide, {headVel=200, headAmp=15}) -> {gain,deficit,saccadePresent,saccadeAmp,
                                                        saccadeToSide,inhibitedFloored,abnormal,...}  [H4][H5]
   STAGE 3 — head impulse (vHIT). At the impulse velocity the INHIBITED canal hits the inhibitory cut-off
   (0 Hz, `inhibitedFloored`) → the VOR velocity is carried SOLELY by the EXCITED canal
   (ipsilateral). gain = the excited modulation / the ideal one. deficit → a corrective SACCADE (overt when
   ≥2.5° ≈ gain<0.83), directed opposite to the impulse (`saccadeToSide`). CENTRAL: gains≈1 →
   a normal HIT (ominous). Calibration S_HZ=0.8 → cut-off ~tone/S≈112°/s < the vHIT velocity.
   STAGE 7 (E2): the second argument is POLYMORPHIC — 'P'/'L' (horizontal, as above, numerically unchanged) OR {canal,ear}

   STAGE 4a — a "leaky" integrator: at gaze θ the drift toward center = θ/τ (slow phase), the fast phase
   toward the gaze. Healthy τ≈25 (negligible drift); central τ≈1–3 → a DIRECTION-CHANGING nystagmus.
   nystagmusAtGaze sums the beat velocities: SPONTANEOUS (peripheral, fixed) + GAZE-EVOKED (central, changing).
   directionChanging requires visibility ≥VIS_THRESH(2°/s) on BOTH sides and opposite directions

 skew(p) -> {present,central,skewDeg,sign,hyperSide,torsionDeg}                                  [H7]
   STAGE 4b — skew deviation / OTR from graviceptive asymmetry (otoliths + MLF). present when |skewTone|≥1°.
   central when |skewTone|≥SKEW_CENTRAL(2.5°) — only a SIGNIFICANT skew counts as a CENTRAL feature (INFARCT);
   a small skew (e.g. the utricle of the superior nerve) present, but NOT central (avoids a false "stroke" — a review fix).

 svv(p) -> {tiltSide, deg, abnormal}                                                             [H22]
   STAGE 7 — SUBJECTIVE VISUAL VERTICAL (SVV): the graviceptive tilt = f(utricle + VERTICAL canals AC/PC).
   The vertical tilts TOWARD THE AFFECTED SIDE (the graviceptively weaker one). MORE SENSITIVE than skew deviation: an
   INFERIOR neuritis gives ~2.5° of tilt DESPITE a normal skew (skew from the utricle=0). Symmetry (BVH)→0. abnormal when ≥2°.
   Does NOT affect the HINTS verdict (a supplementary readout).
 vemp(p) -> {cVEMP:{L,R,ampL,ampR,asym,weakEar,organ,nerve}, oVEMP:{...}}                         [H22]
   STAGE 7 — VEMP: cVEMP(cervical)≈SACCULE→INFERIOR nerve (ipsi); oVEMP(ocular)≈UTRICLE→SUPERIOR nerve. Amplitude from the
   organ's function (sacculeL/R, utricleL/R ∈0..1). Status: ≥0.65 normal / ≥0.3 reduced / <0.3 absent. It separates
   the branches: INFERIOR neuritis→cVEMP↓+oVEMP normal; SUPERIOR→the opposite; BVH→both bilaterally. weakEar = the weaker ear.

   Presets: normal · neuritisR/neuritisL (PERIPHERAL: tone↓ + gain↓ of the affected canal, flocculus intact,
   integrator normal, no skew) · strokeCentral (CENTRAL: canals INTACT gain≈1 → a normal HIT,

   DYNAMIC gain (HIT) are SEPARATE parameters — that is why a stroke gives a nystagmus with a normal HIT.

 compensate(p) -> {vnL, vnR, c, lesionEar, clampAmt, paceAmt, pacemakerBias}                    [H10][H11]
   STAGE 6 — STATIC compensation. The activity of the vestibular NUCLEI (VN) after neuroplasticity — it is this
   (not the raw labyrinth) that push-pull "sees" (spontaneous). Two-track: a CEREBELLAR CLAMP lowers the healthy
   nucleus (early, contribution exp(−c/CLAMP_TAU)) + an intrinsic PACEMAKER raises the affected nucleus (late, persistent).
   clamp+pacemaker = c·gap (restored) → symmetry at c=1 WITHOUT overshoot. c=0 and bias=0 → an exact
   NO-OP (vnL/vnR = afferent(tone,0)) — consistent with stages 1–5.
   STAGE 6b — pacemakerBias (sticky, [Hz]): a latched pacemaker charge INDEPENDENT of the current tone.
   When the labyrinth recovers function, the affected nucleus (tone returned + charged bias) becomes STRONGER →
   a RECOVERY nystagmus (Bechterew's) beating toward the EARLIER affected ear. The scalar c carries no history —
   which is why the charge is a separate, persistent parameter (flag spontaneous().bechterew).

   the MECHANISM (when/why the system switches to prediction).

 verticalBeat(p) -> {v, t, mag, spvV, present}                                                   [H15][H16]
   E3 — the VERTICAL-TORSIONAL component of the spontaneous nystagmus from the vertical-canal PAIRS. imb = (ANTERIOR −
   POSTERIOR activity)/R0 per plane (LARP, RALP): the anterior more active → downbeat + torsion (LARP toward L, RALP toward P);
   the posterior → upbeat + reversed torsion. PER-PAIR summation guarantees CANCELLATION under symmetry (BVH → vector 0)
   despite different AC/PC magnitudes. Compensation shortens it the same as the horizontal (scale 1−c). Merged in spontaneous.
   (TORS_V=0.8 — a simplified torsion contribution; real geometry ~0.78–1.0.)

 pressureStimulus(p, {type, intensity, sign}) -> {present, ear, kind, h, v, t, dir, tdir, vdir, spv, strength}  [H18]
   STAGE 7 (E4) — SCDS / the TULLIO phenomenon. Dehiscence of the SUPERIOR canal (p.dehiscence = "L"/"P") = a MOBILE
   THIRD WINDOW: sound/pressure (type: sound|valsalva|hennebert|pressure) deflects the superior canal's cupula
   WITHOUT head movement → a VERTICAL-TORSIONAL nystagmus. sign: + EXCITATION (default per PRESSURE_EXC; downbeat +
   torsion TOWARD the affected ear) / − INHIBITION (suction; reversal to upbeat). intensity∈[0,1] scales the slow
   phase (spv = SPV_MAX·intensity), the direction vector normalized. AT REST SILENCE: dehiscence ≠
   hypofunction (tones/gains normal → no spontaneous nystagmus, a NORMAL canal vHIT) — the sign appears
   ONLY on stimulus. This distinguishes SCDS from neuritis (there a tonic/gain loss).
   DESIGN DECISION (anterior-canal torsion vs the NYS_SHOW mask): the anterior torsion is the
   DISTINGUISHING SIGN of SCDS, but quickPhase masks it to 0 (the "pure downbeat" convention for BPPV). So as NOT to
   violate the global mask (BPPV rendering/test regression), the Tullio vector is built from the FULL
   geometry Vestibular.nysMag (exported for this purpose), with a LOCAL bypass of the mask. The mask remains
   globally in force. (details and alternatives → the "CLINICAL MASK" section at the top of the file).

 caloric(p, {ear, temp}) -> {ear, temp, spv, beatEar, dir, fixationIndex, failsSuppression, caloricGain, Vcal, Vsp}  [H21]
   STAGE 7 (E4.5) — a single irrigation. The caloric = a LOW-frequency (~0.003 Hz) HC test, the other end
   of the characteristic relative to vHIT (~5 Hz); it scales with a SEPARATE `caloricGain` (not the HF `gain`) → that gives the DISSOCIATION.
   The stimulus = a thermal drive on the HC of the irrigated ear: WARM excites (beats TOWARD it), COLD inhibits (COWS).
   The spontaneous nystagmus (darkness) SUPERIMPOSES (→ DP). The fixation index = suppression by fixation (flocculus → central).

        head-impulse / nystagmus / test-of-skew triad. NEW unilateral hearing loss in an acute vestibular
        syndrome raises suspicion of an AICA-territory infarct (the labyrinth is supplied from that
        territory), so it enters the result as an ALARM FEATURE. The direction works ONE WAY ONLY: the
        presence of hearing loss raises concern, its absence excludes nothing (labyrinthitis produces the
        same picture) — which is why, in the OTOREPO model, the answer "symmetric hearing" carries a
        NEUTRAL weight rather than "supports peripheral". Together with [H8] (HINTS/INFARCT), [H9] (context
        and limits) and [H24] (GRACE-3: gait ataxia = central; HINTS inaccurate without training) it forms
        the complete basis for Block 12.

SIMPLIFICATIONS / CAVEATS:
  - HORIZONTAL UVH nystagmus: torsion as a fixed fraction of the horizontal (TORS_FRAC=0.5) — illustrative; the VERTICAL canals
    (stage 7/E3) are composed realistically PER coplanar PAIR (verticalBeat), but with a simplified TORS_V=0.8;
    the HINTS RENDERER draws horizontal + VERTICAL + torsion (added in U4: neuroNysParams Av/vDir; the inferior-nerve downbeat visible);
    the animation is GATED by the visibility threshold (strength < VIS_THRESH/SPV_MAX → 0), so as not to show sub-threshold
    gaze-evoked drift of the healthy (τ=25 → 0.8°/s) — consistent with the label (spv<VIS_THRESH = "no nystagmus");
  - vHIT: a single gain value (the excited canal); covert/overt saccades as a TEMPORAL SPLIT of the total
    correction (share from the neck-ocular fusion), without the full eyeball velocity dynamics;
  - a linear integrator (drift θ/τ) without horizontal/vertical asymmetry and without rebound nystagmus;
  - skew as a scalar vertical divergence; no full OTR geometry (head tilt, cyclotorsion);
  - compensation: a single scalar c (without a time axis hours↔weeks); clamp/pacemaker as pure functions of c;
    the pacemaker charge (Bechterew) as a sticky parameter (a carrier of history), because the scalar c carries no memory;
  - neck-ocular fusion and velocity storage: phenomenological (weight ∝ reliability / c), without a full Kalman
    filter; head-shaking nystagmus omitted (a latent velocity-storage asymmetry after compensation);
  - HINTS as an EDUCATIONAL model — it does NOT replace an examination; valid in AVS with a persistent nystagmus,
    interpret with HINTS "plus" (hearing) and context (Tarnutzer 2011 [H9]). NOTE: a compensated peripheral loss
    can have a bedside HIT "normal" (covert saccades) — a pitfall when the AVS nystagmus is no longer present.

OBSERVATIONS OUTSIDE THE MODEL — what the BPPV engine does NOT compute (Block 8)
================================================================================
The "Nystagmus" step lets the clinician record what they SAW in the patient. Some of the features
the form asks about have NO counterpart in the engine — and that is written down explicitly, so
that nobody mistakes the model's silence for its prediction. The "Compare with the model's
prediction" card returns the verdict `nieporownywalne` (not comparable) for them, never `rozne`
(different).

1. EFFECT OF VISUAL FIXATION. The BPPV engine has no fixation parameter. Verified: the key set of
   `Vestibular` (isExcitatory, quickPhase, nysMag, nystagmus, gHead, qSupineYaw, qPitch, position,
   simulateCanalith, simulateCupulolith, dynNystagmus, nystagmusPhase, fatigueFactor, qmul, qconj,
   qaxis, rotate, GEXC, CANAL_NORMALS, CUP_WEAK) contains not a single one. Fixation suppression
   exists EXCLUSIVELY in NeuroVOR (see [H3]) and is read only by the HINTS screen. Clinically the
   feature matters (peripheral nystagmus is suppressed by fixation, central is not), so the field
   stays in the form — with weight 1 and an explicit annotation next to the question.

2. DIRECTION REVERSAL ON SITTING UP. The model has no sitting-up phase in the diagnostic test:
   `DIAG.dix.phases` is a SINGLE phase, and `engineXi` builds its time axis from one segment
   {q, tTrans, tHold}. The liberatory transient described above (maneuver dynamics) has THE SAME
   SIGN as the primary excitation and is not a reversal. The field stays in the form with weight 1.

3. VERTIGO ACCOMPANYING THE NYSTAGMUS. The criterion is not in the repository — `baranyClassify`
   has no such row in `crit[]`. We do NOT fill the gap with an invented criterion; we name it here
   so that Block 9 knows what is missing.

DURATION AS A CLAIM, NOT AN ANIMATION PARAMETER
The positional-test simulation window (`XI_OKNO_PRZEMIJAJACY`, `XI_OKNO_UPORCZYWY` in maneuvers.js)
stands for CLINICAL TIME, not animation convenience. The two numbers have different status:
  - canalithiasis — the duration is set by PHYSICS. Measured natural decay (|xi| < 3% of peak):
    posterior 29.75 s, horizontal 39.85 s, anterior 34.35 s. The window (55 s) must ACCOMMODATE
    that decay, not define it.
  - cupulolithiasis — xi does NOT decay (|xi| = 1.000 of peak even after 300 s), so tEnd IS the
    window and nothing else. That number (75 s) is a clinical claim outright and must exceed the
    60 s threshold the app prints next to the animation.
Gate: npm run barany:check. The golden pins VALUES but does not express RELATIONS — which is why
the previous value (18 s, shorter than the transient form) passed green.

================================================================================
INTERPRETATION — WHAT THE MODEL CAN SETTLE, AND WHAT IT CANNOT (Block 9)
================================================================================
The "Interpretation" step leads from a RECORDED observation to canal, side and mechanism. It holds
no second, independent set of clinical rules: that would be a third description of the same
knowledge (after the engine and `baranyClassify`) and would drift apart at the first parameter
change. Instead we ENUMERATE 20 candidates (test x canal x side x mechanism) and check which of
them the recorded observation EXCLUDES. A candidate falls when even one recorded DECISIVE feature
contradicts the model's prediction. No scoring, no percentages, no ranking.

"Agreement" describes the RELATION of the record to a pattern, not the state of the patient, and
has NO numeric form. A number next to a canal name would read as the probability of a diagnosis in
this patient.

LIMITS OF DECIDABILITY — MEASURED ON THE ENGINE'S PREDICTIONS
The four statements below are claims about the MODEL, not about the examiner's diligence. The app
states each of them explicitly on the interpretation screen, each with its own distinct reason.

1. DIX-HALLPIKE: the direction gives the SIDE (torsion +-1) but NOT the mechanism. Canalithiasis
   and cupulolithiasis have an identical direction {h:0, v:+0.93, t:+1} — they differ only in
   `strength` (1.00 vs 0.60), which the form does not measure. The mechanism follows EXCLUSIVELY
   from the dynamics (latency, duration, fatigability), and those are the same in ALL tests, so no
   further positional test will settle it.

2. ROLL TEST: the direction gives the MECHANISM (geo/apo), while the side comes only from the
   ASYMMETRY OF INTENSITY — and in opposite directions for the two mechanisms: canalithiasis, the
   affected ear STRONGER (1.00/0.45); cupulolithiasis, the affected ear WEAKER (0.27/0.60). This is
   the only one of the four missing-side cases that can be fixed by RECORDING more, so the screen
   asks for a specific feature instead of declaring a limitation of the model.

3. BOW & LEAN: the ambiguity is STRUCTURAL. (canalithiasis, one ear) and (cupulolithiasis, the
   other) produce an IDENTICAL pattern, and the intensity is symmetric — measured: 4 candidates
   yield only 2 disjoint prediction fingerprints. No further description of THIS test will separate
   them; the roll test does.

4. DEEP HEAD-HANG: all 4 candidates have the same direction {h:0, v:-1, t:0}. The side is
   NOT DERIVABLE — a consequence of the simplification described above (the anterior canal drawn as
   a pure downbeat), not a lack of data. NO test in this model will establish it.

THE SUGGESTED NEXT TEST IS DERIVED, NOT WRITTEN DOWN
There is not a single hand-written "test -> test" pair in the code. We ask the model: do the
candidates that survived have DIFFERENT predictions in another test (`odciskPredykcji`)? The
fingerprint covers the direction per phase AND the relation of intensities between phases; without
the intensity relation, (canalithiasis,R) and (canalithiasis,L) have an identical direction
fingerprint in the roll test, so the roll would look like a test that does not separate them — and
it is the only one that establishes the side of the horizontal canal. Measured: the roll has 4
disjoint fingerprints with intensity and only 2 without it.
An empty suggestion list is a CLAIM ("no test will separate this"), not a gap. Sending the
clinician to an examination that cannot contribute anything would be worse than silence.

AN ATYPICAL PICTURE DOES NOT LEAD TO A MANEUVER (acceptance criterion 3)
`recommend()` ALWAYS returns a first-line maneuver and remains UNTOUCHED — it is simply not called
when `nietypowy()` is true. The alarm is computed over ALL records of the session, not over the
current test: otherwise the advice "do the next test" would clear it, because a downbeat recorded
in the Dix-Hallpike would vanish from memory on switching to the roll. Quarantine ("unreliable
observation") silences the CONCLUSION but NOT the alarm — `interpretuj` performs a second, CONTROL
pass including the quarantined fields, and if that pass leaves no candidate at all, the picture
stays atypical.

SOURCE OF THE MECHANISM
`state.variant` drives the animation, the feature chips, the Barany classification and the choice
of maneuver. Until Block 9 it looked identical in three different situations; the most dangerous of
them — "it is left over from the previous screen, because the animation has to draw something" —
posed as a conclusion. `state.variantZrodlo` tells them apart explicitly: derived (by an explicit
gesture, and only when exactly one mechanism remains) / manually overridden / none. Changing the
record removes the derivation but NOT the mechanism: the animation has to draw something, only the
claim about its source disappears.

Gates: npm run interp:check (pure model, bare Node) and npm run interp:dom (a DOM scan in jsdom —
criterion 3 is a claim about the SCREEN, not about the model).

================================================================================
MANEUVER AND EXPERT MODE — WHAT THE MODEL SELECTS, AND WHAT IT DOES NOT MEASURE (Block 10)
================================================================================
The "Maneuver" step guides the repositioning and — in expert mode — selects a maneuver for a user
who already knows the canal, side and mechanism. There is not a single hand-written
"canal+mechanism -> maneuver" pair: we ask `recommend()`, the same source the diagnostic path uses.
The canal->test bridge is derived from DIAG, because `recommend()` has a SILENT DEFAULT (anything
other than 'dix' and 'headhang' falls into the horizontal-canal branch), so a typo in the key would
not raise an error — it would return a maneuver for the wrong canal.

WHAT THE SELECTION CARD MAY SAY, AND WHAT IT MAY NOT
The mockup captions the recommended maneuver "highest agreement with the diagnosis". The model does
not compute agreement with the diagnosis of this patient — it computes the FIRST-LINE MANEUVER PER
THE GUIDELINES for the canal and mechanism the USER PROVIDED. The card says exactly that, and it
also names which of the three values really came from a human: `state.side` holds the literal 'P'
and `state.variant` the literal 'canalo', so without `sideZrodlo`/`variantZrodlo` the sentence "you
provided the canal, side and mechanism" would be false on first entry — in the very sentence whose
whole purpose is honest attribution.

"UNTIL THE NYSTAGMUS SUBSIDES + MARGIN" IS A FLOOR, NEVER A SHORTENING
This is the most important number in the block and the only one that could harm a patient.
The predicted nystagmus duration comes from the dynamics window `min(cap, seconds) + tTrans + TAIL`,
where `cap` for the "medium" size is 12 s. MEASURED consequences:
  - the number NEVER exceeds ~19 s, no matter how long the position is meant to be held;
  - Semont has `seconds=90` and the instruction "Hold 1-3 min", while the model gives 18.5 s;
  - Gufoni geotropic: 18.4 / 14.1 s against a 60 s protocol;
  - Lempert stage 5 (debris exit): 39.8 s against 30 s — here the mode genuinely EXTENDS.
The mode may therefore ONLY RAISE the protocol time. Setting the number directly would shorten the
Semont drop by ~70 s below the lower bound of the app's OWN instruction, and with auto-advance on it
would move the patient along by itself. For cupulolithiasis the mode is UNAVAILABLE: xi does not
decay (measured |xi| = 100 % of peak even after 300 s), so "until it subsides" has no referent.
Gate: npm run man:check (section D); failing-first proof = 54 violations across the grid
maneuver x side x size x stage.

DEBRIS EXIT IS A SEPARATE AXIS, NOT A TIMING CRITERION
In the Epley the debris leaves the canal during the SIT-UP step, which has NO countdown. Forcing
both facts into one field would mean concealing one of them — for the very step in which the
liberatory nystagmus arises. For vertical canals the exit stage comes from PHYSICS (`manExitStep`);
for the horizontal canal and cupulolithiasis it comes from a SCHEME (n-2), and the screen admits
that instead of presenting a rule as a measurement.

POSITION NAMES HIDE AN INVERSION
`sideL` means "on the LEFT side", but `leanL` means "on the RIGHT side": the Semont poses are named
after the direction of the TILT, not after the side the patient lies on. A mistake here would print
the wrong ear at the bedside, and the physics would not react, because the name never enters the
simulation. The oracle checks these names against the SIGN OF GRAVITY in the head frame, not
against the comment.

POSITION TIMER: WALL CLOCK AND THE GAP IN OBSERVATION
The timer summed `dt` from rAF frames. That looks like "it stops when the screen goes dark", but
`last` is a closure variable that nobody touches on returning to visibility, while the rAF timestamp
runs in real time — so the first frame after unlocking received `dt` equal to the WHOLE gap and
caught it up in a single jump, together with the end-of-stage condition, the sound and the
auto-advance; for a longer gap, as a cascade all the way to `markConsumed`. Time is now measured by
a wall-clock anchor (`hold-clock.js`, a pure module, WITHOUT `Date.now` — the current time is passed
as an argument so the gate stays deterministic), and `dt` is left to the animation alone.
A gap longer than 3 s is a CLINICAL event: the app can measure time, but it cannot tell whether the
patient held the position while nobody was looking at the screen. It therefore stops the countdown
and asks for confirmation. Shorter blinks do not raise an alarm — an alarm without a reason teaches
people to ignore the message (the same mechanism that kept `dixRep` out of the decision fingerprint).
The warning about the missing screen lock comes from an ACTUAL attempt, not from feature detection:
the lock is sometimes refused despite `wakeLock` being present (no secure context, system policy,
power saving).

LEFT AND RIGHT ALWAYS WITH AN OWNER (acceptance criterion 2)
The criterion was already met before this block — every sentence containing a direction also names
the owner — so we added a RATCHET rather than a fix. The unit is the SENTENCE, not a window of N
characters (a window produced 22 false hits, because "toward the healthy side" can sit 56 characters
before the side name), and the dictionary of forms is CLOSED and taken from the declension table:
a prefix pattern "lew*/praw*" matches Polish words for "correct", "probability" and "improve", so
the gate would fire on text unrelated to direction.
Separately, 29 places were corrected where the NOMINATIVE ("lewa"/"prawa") had been pasted into
accusative, dative and genitive contexts.
The `engine.plans` rebaseline carries a scope proof: after removing the text fields the plan diff is
EMPTY, i.e. `body/yaw/face/seconds/progress` are bit-for-bit — physics and geometry untouched.

WHAT THIS BLOCK DOES NOT DO
The "Post-maneuver control" card from the mockup (resolution / partial improvement / no improvement /
canal conversion / suspicion of the other side / residual dizziness / unreliable examination) is
Block 11 of the document and the `followup` step, which stays `pending`. Block 10 prepares the ground
for it: the canal-conversion signal after a PERFORMED maneuver already works, because `consumed` used
to silence not only the sentence "the conclusion is out of date" (rightly) but also "the current
inputs point to a DIFFERENT canal" (wrongly) — and that is an indication for a NEW maneuver, not a
charge against the old one.

Gates: npm run man:check (pure model, bare Node) and npm run man:dom (a DOM scan in jsdom —
acceptance criteria 1 and 3 are claims about the SCREEN, not about the model).

================================================================================
POST-MANEUVER CONTROL — WHAT THE APP RECORDS, AND WHAT IT DOES NOT KNOW (Block 11)
================================================================================
The "Follow-up" step closes the clinical process and handles outcomes other than immediate
resolution. The answer to "what do you observe now?" is the CLINICIAN'S OBSERVATION, not the app's
conclusion: the model does not judge whether the repositioning succeeded — it derives the NEXT STEP
from the answer. This is the same boundary Blocks 6, 8 and 9 hold: the questionnaire picks a
pathway, the form describes an observation, the interpretation eliminates candidacies, and none of
them makes a diagnosis. Clinical basis: [H25] (AAO-HNS BPPV guideline update, 2017).

SEVEN ANSWERS, THREE OF WHICH FORBID REPOSITIONING
The vocabulary is CLOSED: no "other" entry and no text field (acceptance criterion 3 starts with
there being nowhere to type a name). Three answers take away the screen's right to offer a
maneuver, each for a DIFFERENT reason and each with the reason WRITTEN OUT:
  • canal conversion — the debris is in another canal, so the same maneuver would treat a canal it
    is no longer in; an alternative for the same canal does not address the target canal either;
  • residual dizziness — without positional nystagmus there is NOTHING to reposition, and the
    phenomenon is described after SUCCESSFUL repositioning and is usually self-limiting (days to
    weeks);
  • unreliable examination — an assessment the clinician themselves called unreliable does not
    justify another repositioning; the step gets the status "unreliable", NOT "done" (the same
    error Block 8 cut out at lateralization).
Greying a button out without giving a reason would be silence, not a warning, so forbidden actions
are not buttons at all — they are a sentence under "what this screen deliberately does not offer".

ACCEPTANCE CRITERION 1 — THE END OF A MANEUVER IS NOT A RETURN TO THE START
Measured before the change: `zakonczSerie` called `backToSetup()`, i.e. the series ended EXACTLY
where it began — on the canal list, without a single sentence about what had happened and with no
place for the control result. Reaching the last stage SEQUENTIALLY still navigates nowhere:
"performed" is a state of the maneuver, not a navigation command.

ACCEPTANCE CRITERION 2 — CONVERSION LEADS TO RE-INTERPRETATION
The model returns the list of FORBIDDEN actions separately from the offered ones, and the screen
does not render the forbidden ones. The gate reads the rule table DIRECTLY, and that is not
over-zealousness: `nastepneKroki` filters out forbidden actions, so adding "repeat the maneuver" to
the conversion step list did NOT change the function's result — the mutation passed the entire
oracle. The filter protects the screen but stops guarding the source. In expert mode (no test)
"re-establish canal and side" targets the selection screen, not the interpretation screen, which
without `testKey` has nothing to build itself from.

ACCEPTANCE CRITERION 3 — ENDING WITHOUT IDENTIFYING DATA
The criterion was already met before this block (there is not a single text field in the app), so
we added a RATCHET rather than a fix — the same move as for criterion 2 of Block 10. The gate scans
EIGHT screens with a structural pattern (a field tag, not a word); `type=range` sliders are allowed,
because they are model parameters, not data. The other half is the RECORD GUARD: it walks the
finished record and REJECTS it instead of quietly cleaning it — sanitizing would produce a record
that looks saved while part of its content is missing (a lesson from the VOG track). The rule is
structural: every value must come from a closed vocabulary or be a number, so a string outside the
vocabulary is a violation regardless of what it means. Ending the session has NO precondition — the
first version had the button inside the "What next" card, which only renders after an answer is
chosen, i.e. the session could not be ended without selecting something.

SERIES HISTORY: THE TIMES ARE FROM THE PLAN, NOT MEASURED
Repeating a maneuver is a NEW performance (a new flow record, a new entry); otherwise three
repetitions would look like a single attempt in the summary. The entry carries times FROM THE PLAN
(protocol or set with the slider) and says so explicitly: the app counts one stage at a time and
does not sum the time across the maneuver, so calling it "execution time" would be a fiction. The
entry CARRIES NO CLOCK — first, the golden snapshot must stay deterministic; second, the time of
the examination is a datum that, together with the rest, moves the record toward patient
documentation.

BEFORE AND AFTER
The pre-maneuver description is COPIED at the moment the maneuver is considered performed. Without
that copy the comparison would disappear exactly when its second half comes into being: observation
records are keyed by TEST, so describing the control test overwrites the description from before
the maneuver. The card admits that the "after" column fills in only once the control has been
described feature by feature in the "Nystagmus" step — the answer on this card does not replace it.

WHAT THIS BLOCK DOES NOT DO
The session summary lives ONLY in this session's memory: the app does not store it on the device
and does not send it anywhere. Persistent state and the examination-report generator are Block 15
of the document — writing clinical data to disk is a separate decision (consent, retention,
deletion), not a side effect of the "Follow-up" step. The control result is prepared for that
generator: `podsumowanieSesji` returns only identifiers from closed vocabularies, so the labels are
added by the screen.

Gates: npm run fu:check (pure model, bare Node, invariants over the full product of 588
combinations) and npm run fu:dom (a DOM scan in jsdom — all three acceptance criteria are claims
about WHAT THE APP DOES, not about the model).

THE HINTS/HINTS+ EXAMINATION WITH QUALIFICATION — TWO TRACKS, ONE DOOR (Block 12)
════════════════════════════════════════════════════════════════════════════════════════════════
Sources: [H8] Kattah 2009 (HINTS, the INFARCT mnemonic) · [H9] Tarnutzer 2011 (context and limits) ·
[H24] GRACE-3 2023 (the timing-and-triggers taxonomy; gait ataxia = central; HINTS inaccurate without
training) · [H26] Newman-Toker 2013 (the "plus" = a hearing screen).
Gates: npm run hints:check (pure model, bare Node, invariants over the FULL product of 14,400
examination states) and npm run hints:dom (jsdom, the real module graph — all three acceptance
criteria are claims about WHAT THE APP DOES).

TWO TRACKS THAT MUST NOT BE CONFUSED
The HINTS module now holds two things that work in opposite directions:
  • the SIMULATOR (screen `hints`, the NeuroVOR engine) — you pick a pathology and the model shows
    how the eyes will behave. It teaches the PATTERN;
  • the EXAMINATION (screen `hintsBad`, src/app/hints-model.js) — you record what you SAW in the
    patient and the app organizes the observations. It records the OBSERVATION.
The separation is physical (separate screens, separate state, separate oracles) for the same reason
Block 8 tore the observation form away from the animation of the PREDICTED nystagmus: as long as the
form sits next to the model, "agreement" measures only whether someone copied the screen correctly.
The examination model does not import the engine, and the oracle enforces that (gate J12).

ACCEPTANCE CRITERION 1 — ONE DOOR
Measured BEFORE the change: SEVEN of seven entry paths into the module went through with an EMPTY
qualification (tiles 2 and 5 of the start screen, the HINTS tab, openHints, openHintsCustom, the
"Laboratory" area, and the `#p=` link carrying a shared patient), while the only gate in the app —
`triageGo` — sat on a path none of them touched. Today the door is ONE: the qualification screen,
with `wolnoBadac` behind it. Entry exists in exactly two ways:
  • qualification CONFIRMED — the answers form an acute vestibular syndrome (continuous dizziness
    with sustained spontaneous nystagmus, no red flags);
  • qualification DELIBERATELY SKIPPED — the user picks a REASON from a closed vocabulary (teaching
    demonstration / simulation / qualification done outside the app / proceeding despite the advice
    against it). The reason enters the result as a caveat and stays there for the rest of the
    session; for "demonstration" and "simulation" the result says explicitly that THIS IS NOT A
    RECORD OF A PATIENT EXAMINATION.
The refusal is not silent: the screen states that it did not let you in and says what is missing.
The qualification reads THE SAME `triage` state as Block 6 — two different questionnaires about the
same patient could say two different things, and the user would have no way to guess which holds.

The `#p=` link is gated most firmly of all seven, deliberately: a shared link can seat a clinician
straight in front of the verdict "peripheral pattern — reassuring", computed for the PARAMETERS IN
THE LINK rather than for the patient sitting in front of them.

EXAMINER TRAINING AS A FIELD, NOT A LEGAL DISCLAIMER
GRACE-3 [H24] states plainly that HINTS performed without training is inaccurate. We ask ONCE, in the
qualification, and the result carries the answer itself — instead of making the user tick "unreliable
examination" every time. A lack of training (or a missing answer) does not block the examination, but
it REMOVES THE REASSURING VALUE of the result: a full peripheral set then drops from "pattern
supporting a peripheral lesion" to "peripheral pattern, but with no reassuring value".

WHY THE OPTIONS ARE NOT CALLED "NORMAL / ABNORMAL"
The user document describes the choices as "normal, abnormal, cannot assess". We keep the SHAPE (big
choices, always an explicit "cannot assess") but not those two labels — because in HINTS they INVERT,
and that inversion is the whole point of the test. A NORMAL head impulse in a patient with an acute
vestibular syndrome is the DANGEROUS finding (the "Impulse Normal" of INFARCT [H8]), and an ABNORMAL
one is reassuring. A button labelled "normal" above a finding that means "rule out a stroke" would be
the worst label in the entire app. The options therefore name WHAT IS SEEN ("corrective saccade" /
"the eyes stay on target"), and the meaning is added by the result. The oracle keeps this as a
RATCHET (gate B7), so nobody "fixes" it back to the document's literal wording.

SIX COMPONENTS — AND WHY THREE OF THEM WEIGH DIFFERENTLY
The core (HI · N · TS) settles the conclusion. The "plus" (hearing) and gait may ADD an alarm feature,
but on their own they never create a reassuring result: symmetric hearing removes one alarm feature
and adds nothing in the other direction [H26], and walking unaided is consistent with a peripheral
cause but does not substitute for the triad. Every component carries three texts: the INSTRUCTION
(how to perform it), the MEANING (what follows from it) and the TRAP (what this element does NOT
tell you). The trap is the clinically most important field here — without it the module would teach
that a negative test of skew excludes a stroke.

TWO COUPLINGS BETWEEN COMPONENTS (which no on-screen label can express)
  • "Impulse Normal" is an alarm feature ONLY when spontaneous nystagmus is present. In a patient
    without nystagmus a normal head impulse is simply normal — reading it as "central" would be a
    false alarm in the commonest outpatient situation. When the nystagmus was NOT ASSESSED the result
    is not an alarm either, but the conclusion still cannot come out reassuring, because the core is
    incomplete.
  • Saccades on BOTH sides do not support a peripheral cause in the HINTS sense: HINTS assumes a
    UNILATERAL acute vestibular syndrome, whereas bilateral vestibulopathy produces saccades
    everywhere and looks reassuring in the face of real, severe loss ([H23], BVH).

ACCEPTANCE CRITERION 2 — "CANNOT ASSESS" IS NOT A NORMAL RESULT
Written down FOUR times, at four different levels, because a single place could be bypassed by
accident:
  1. option weight: "not assessed" never enters the list of findings supporting a peripheral cause;
  2. conclusion: "pattern supporting a peripheral lesion" REQUIRES a complete core — one unassessed
     HINTS component is enough to make a reassuring result impossible;
  3. screen: unassessed components are LISTED BY NAME in a separate list, so they cannot be passed
     over in silence;
  4. appearance: the "cannot assess" option has a dashed outline and a square box instead of a round
     one — it differs from an answer before anyone reads the label.
We separately guard the difference between "not answered yet" and "cannot assess": touching the same
answer again REMOVES it and returns to the unanswered state. If undoing an answer set "cannot
assess", the user would be marking a missing assessment through sheer hesitation.

SIX CONCLUSIONS — AND ONE THAT CAME OUT OF A BUG
The conclusion "incomplete examination" says "not all three components were assessed". The first
version of the model also dropped into it the states where the core WAS assessed but did not form a
peripheral picture (saccades on both sides, a normal HIT without nystagmus) — that is, it displayed
an UNTRUE label over an examination that had been carried out in full. Hence the separate conclusion
"examination performed, result inconclusive": it leads to a different action than "finish the
examination".
The order of the checks is a REQUIREMENT, not a matter of style: the alarm comes first, before
"HINTS does not apply here" and before "incomplete examination", because a present skew deviation or
an inability to walk unaided mean the same thing regardless of whether the rest of the examination
could be performed.

THE ASYMMETRY OF UNRELIABILITY
An examination called unreliable CANNOT reassure, but it does NOT cancel an alarm feature that was
noticed. "I was not sure" does not erase what you saw. This asymmetry is checked in both directions
over the whole product of answers (gates D10 and F5).

ACCEPTANCE CRITERION 3 — WHAT "A CLEAR WARNING" MEANS
The warning exists IF AND ONLY IF an alarm feature was marked (the equivalence is checked in both
directions over 14,400 states), it stands ABOVE the conclusion, it carries role="alert", it names the
features that triggered it, and it repeats the management from the red-flag card of Block 6: urgent
neurological evaluation, MRI with diffusion (DWI) and angiography (MRA), CT is NOT suitable for ruling
out a posterior-fossa stroke, early MRI can be false-negative (repeat after 48–72 h). Two different
sentences about the same management would mean that one of them is out of date.

WHAT THIS BLOCK DOES NOT DO
  • It makes no diagnosis and excludes no stroke. The peripheral result states outright that it is a
    BEDSIDE result, and an empty list of alarm features states outright that it is NOT an exclusion of
    a central cause.
  • It writes nothing to disk. `wpisHints` prepares a record from closed vocabularies for the
    examination-report generator (Block 15), and the guard `bezDanychOsobowychHints` REJECTS that
    record whenever anything outside the vocabulary appears in it — rather than silently cleaning it.
    Sanitization would be worse than refusal: the record would look saved while the data vanished
    without a trace.
  • It measures no time. The record carries no clock — for the same two reasons as the follow-up
    record (the golden snapshot must stay deterministic + the time of the examination is patient data).
  • It does not judge the components for the user, and there is NOT A SINGLE text field on any of the
    three screens, so entering patient data is structurally impossible.


════════════════════════════════════════════════════════════════════════════════════════════════
LEARNING MODE AND CASE LIBRARY — THE KEY IS COMPUTED, NOT WRITTEN IN (Block 13)
════════════════════════════════════════════════════════════════════════════════════════════════
Gates: npm run nauka:check (pure model, bare Node) and npm run nauka:dom (jsdom, the real module
graph). Acceptance criteria K1, K2 and K4 are claims about the model and the screen; K3 needs
a layout engine, so it was MEASURED IN THE BROWSER and the result is recorded below.

THE PRINCIPLE: A CASE CARRIES NO ANSWER KEY
A library of teaching cases is the most natural place for this app to start lying. It would be
enough to write a field `diagnosis: 'posterior canal, right, canalithiasis'` into a case — and from
that moment there would be a SIXTH description of the same clinical knowledge (after the engine,
`baranyClassify`, `interp-model`, `man-model` and `followup-model`). It would drift at the first
parameter change while the quiz stayed green, because it would be checking agreement with its own
answer. A case therefore carries the HISTORY (the `triage-model` vocabulary) and the OBSERVATION
(the `obs-model` vocabulary), and the key to each of the six stages is COMPUTED by the same model
the clinical path uses:

  stage "prediction"   → direction patterns from `odciskPredykcji` for this provocation and side
  stage "recognition"  → `interpretuj().pozostale`, gated by `nietypowy()`
  stage "mechanism"    → `interpretuj().mechanizm` (null = the model does not settle it)
  stage "maneuver"     → `recommend(provocation, mechanism)` via `doborZProby`
  stage "follow-up"    → `REGULY_KROKOW[result]` from Block 11, with its prohibitions and reasons

A change in the engine changes the lesson or turns an oracle red; there is no third option. Gate A8
forbids a case to carry a field named `rozpoznanie`, `kanal`, `strona`, `mechanizm`, `manewr` and
six others, and section B proves BY MEASUREMENT that the key comes from the engine: reversing one
torsion field in the record reverses the side in the key, and swapping the dynamics changes the
maneuver from Epley to Semont.

FOUR END-OF-CASE FIELDS — THREE COMPUTED, ONE AUTHORED
The document requires every case to end with a decisive feature, a trap, an alternative and a next
step. Three of them the model already computes (`rozstrzygajaca`, `wykluczone`/`pozostale`,
`sugerowaneProby` or `REGULY_KROKOW`). Only the TRAP is authored — and that is why it is the one
field the oracle polices by CONTENT: it must point at a feature or a flag genuinely present in that
case (A9), so that no moral unrelated to the picture can be attached.

ACCEPTANCE CRITERION 1 — THE ANSWER IS NOT HIDDEN, IT DOES NOT EXIST
`informacjaZwrotna()` returns null until a decision has been made, and it is the ONLY entry to the
verdict, so the screen has nothing to hide or reveal. The jsdom oracle measures this on
`#app.innerHTML`: before the decision there is no feedback card, no `data-nwerdykt` attribute and
no observation record (that one is COVERED until the prediction — otherwise the prediction stage
would be a question about what is visible next to it).
The hint is the third route straight from the document, but it POINTS AT A FEATURE and never gives
the result (gate D10 checks that it carries no canal, side, mechanism or maneuver); it is recorded
and enters the case result.
AN ADDITION THE DOCUMENT DID NOT ASK FOR: an answer once given is FROZEN. Without it, "a decision
before the answer is revealed" would be a fiction — it would be enough to click anything, read the
verdict and correct it. The refusal to record is visible and carries a reason.

ACCEPTANCE CRITERION 4 — A THREE-VALUED VERDICT
`correct` (the only answer this description allows to be proven) / `defensible` (the model does NOT
SEPARATE it from the others) / `incorrect` (the description excludes it). The defensible set comes
from `pozostale` and `alternatywy`, not from an author's declaration — ambiguity is a PROPERTY OF
THE MODEL, not an opinion about the case. The screen names two different kinds of it: "the model
does not know a single answer" (no correct option at all) and "the model does not separate this
answer from the others" (a correct one exists, but irrefutable answers stand beside it). Without
that second signal the screen would fall silent exactly where the whole lesson of the case is to
name the boundary of knowledge.

WHAT THE CRITIQUE FOUND BEFORE THE SCREEN EXISTED
The first version of the model marked as INCORRECT "a pattern this provocation cannot produce".
That was untrue and the most dangerous mistake of the whole block: it promoted a SIMPLIFICATION OF
THE ENGINE into a clinical claim. The model predicts a pure downbeat with no torsional component
for the anterior canal, so a textbook torsional-vertical anterior-canal nystagmus would have been
marked "impossible" for the learner; and a Dix-Hallpike lays the head back and can provoke another
canal too. The carrier of error is therefore the EAR, not "impossibility": the pattern of the other
ear in a one-sided provocation is incorrect, because that is the single mistake that sends
a clinician to the wrong ear. The reason "impossible pattern" was REMOVED from the dictionary and
gate F1 keeps it from coming back.
Second repair: a candidate THAT SURVIVED is never an incorrect answer — not even when the picture
carries a central feature. Otherwise every downbeat in a Dix-Hallpike (which raises `flagaOsrodkowa`)
would erase anterior-canal BPPV from the differential and the learner would leave with the sentence
"downbeat = never BPPV". The app says otherwise: on the diagnostic screen it NAMES the anterior
canal and AT THE SAME TIME withholds treatment. The lesson mirrors exactly that — "atypical picture"
is the correct answer, the candidate stays defensible.
Third repair: at the maneuver stage, "I do not reposition" and any maneuver must never both be
non-incorrect. The app's own model treats observation and repositioning as MUTUALLY EXCLUSIVE
(`REGULY_KROKOW.residual`: `obserwuj` as the main step AND an explicit prohibition on repositioning
with a stated reason), so a lesson allowing both would invert the semantics of its own program.
With an atypical picture, holding back is correct and EVERY maneuver is incorrect; with a typical
picture the reverse. Thanks to this, the case whose entire lesson is to stay one's hand stopped
giving the same verdict to the learner who stopped and the one who did not.

THE DISCRIMINATING-POWER GATE — AND A THRESHOLD REJECTED AFTER MEASUREMENT
A stage on which no answer is incorrect measures nothing while looking assessed. The first threshold
read "at most half the answers may be non-incorrect" and it threw out ALL 13 cases, including those
that faithfully mirror the app's model: for the follow-up result "partial improvement", Block 11
permits four actions out of six. The threshold measured an intuition about quiz sharpness rather
than a property of the model, so it was rejected. What remains is checkable: every stage must have
a CARRIER OF ERROR, with two exceptions stated outright and computed from the model — prediction in
a BILATERAL provocation (there is no ear to be wrong about) and the mechanism when BOTH variants
survive (there is nothing to exclude). On top of that: at least three of the five stages must have
a correct answer.

THE LIBRARY — 13 CASES
Three levels (basic 3, clinical 5, expert 5) and four kinds (classic 4, near-typical 4, multicanal 2,
central 3). The history of the CENTRAL cases looks like BPPV — episodic, positional, no red flags —
and that is their point: if centrality could be read from the history, the case would teach reading
the history rather than the nystagmus. Red flags are taught by Block 6. Gate H8 requires a case in
which NOT A SINGLE candidate survives to carry a flag (f1/f2/f3) — otherwise "matches no pattern"
would pose as a claim about a central cause, while it is only a gap in the engine's vocabulary.

ACCEPTANCE CRITERION 2 — PROGRESS SAVED LOCALLY
All contact with browser storage lives in `nauka-store.js` (the block's only dirty module), so the
pure model runs in bare Node and the golden snapshot stays deterministic: progress is read ONCE,
at boot, outside rendering, and the golden scenarios pin it explicitly. The store is versioned,
resistant to private mode and to a full quota (the refusal is VISIBLE, not silent), and carries only
identifiers from the vocabularies: case, result, stage verdicts, hints used. The guard
`bezDanychOsobowychNauka` checks this before writing and REJECTS the record rather than cleaning it —
silent sanitization would look like a save that never happened. There is no clock: solving time is
data about the user, and the golden snapshot has to stay deterministic anyway.
Entries for cases no longer in the library DO NOT DISAPPEAR silently — they are counted separately
(`nieznaneWpisy`) and shown, because a counter that moves backwards on its own is worse than a number
the user does not understand.

ACCEPTANCE CRITERION 5 (MINE, NOT FROM THE DOCUMENT) — LEARNING DOES NOT TOUCH THE PATIENT
The learning track and the patient track share one state object, and contamination would be PARTLY
IRREVERSIBLE: `decisionSeq` is explicitly monotonic, `obsOdciski` is derived from `obs`, and
`kontrole` is a series history indexed by `flow.maneuver.kontrolaIdx`. The reflex mitigation — "save
the state, run the lesson, restore" — works for none of those three fields and fails silently. The
separation is therefore STRUCTURAL: `nauka-state.js` writes only to `nauka*` fields, the key is
computed on the frozen literal PACJENT_ZERO (never on a spread of the state), and the learning
modules are forbidden to import `state.js`. The oracle takes a fingerprint of 32 fields describing
the patient before and after the lesson — including `decisionSeq` and `obsOdciski`, precisely the two
that any snapshot breaks — and requires them to be identical. The reverse direction too: an ongoing
patient session does not change the content of the lesson.
A consequence of this rule is what the lesson DELIBERATELY LACKS: engine animation and the 3D figure.
Both stand on `state.side`, `state.canal`, `state.variant`, `state.maneuverKey` and `state.plan`, so
showing a maneuver would require overwriting them — and on leaving the learning area the clinician
would find someone else's case on the positioning card, with `variantZrodlo` still saying "derived
from the observation record". The illustration of a case is the OBSERVATION RECORD assembled from
the Block 8 vocabularies.

ACCEPTANCE CRITERION 3 — MEASURED IN THE BROWSER
jsdom has no layout engine, so "no horizontal scrolling" cannot be checked by an oracle.
The measurement: 13 cases × 6 stages, before and after the answer, plus the two library screens.
At 360×720 — 145 measurements, 0 overflows, the furthest right edge exactly 360 px.
At 320×640 — 144 measurements, 0 overflows, the furthest right edge exactly 320 px.
The six-stage axis WRAPS (an `auto-fit` grid) instead of scrolling horizontally: at 360 px, six
items in one row is ~600 px, i.e. half the lesson beyond the edge. The observation-record table uses
`table-layout:fixed` and breaks long values, because that table was the first to widen the row.
At 1280 px the D3 layout was measured: control column 296..676, illustration column 696..1217, both
in one row; the option touch targets are 56 px.

WHAT THIS BLOCK DOES NOT DO
  • It makes no diagnosis and does not grade the clinician. The verdict concerns an answer to
    a SYNTHETIC case and is computed against a model whose limits the same screen names.
  • It shows no result as a number or a percentage. A case result is a PROFILE of stages, because
    a single number would lie in both directions: it would reward hitting where there was nothing to
    hit, and penalize a defensible answer.
  • There is not a single text field on any learning screen, so entering patient data is structurally
    impossible — the same principle as in Blocks 8, 11 and 12.
  • It does not measure solving time and stores nothing beyond identifiers from the vocabularies.
